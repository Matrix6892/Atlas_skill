# Этап M0: что построено и какие решения приняты

Этот документ связывает ТЗ v0.7 с кодом. ТЗ не меняется. Здесь записано, какие открытые решения §8.6 этап M0 принял **временно**, чтобы было что пилотировать, и что осталось открытым.

## 1. Состав этапа (§8.2, строка M0)

| Требование M0 | Где в коде |
| --- | --- |
| Ядро с одной точкой записи: JSON, версия схемы, стабильные ID, подтверждение записи | `atlaskit/store.py` (транзакции, блокировка, атомарная публикация, повторное чтение), `atlaskit/ops.py` (проверка квитанций) |
| Один адаптер: Claude Code, хуки старта и конца ответа | `atlaskit/hooks.py`, `hooks/hooks.json` (плагин) или `.claude/settings.local.json` (скилл без плагина) |
| Сводка агенту | `atlaskit/brief.py` |
| Ручной режим для другого агента, одна сессия за раз | `atlas.py start --agent codex`, блок в AGENTS.md (`connect --agents-md`) |
| Экраны Э0, Э3, Э4, Э7 (ядро); Э5, Э6, Э11, разбор Э9 (агент) | `atlaskit/views.py`; шаблоны агента — `skills/atlas/references/screens.md` |
| В чате: короткая история темы и уборка порции парковки | `atlas.py topic`, `atlas.py parking` |
| Параллельные записи и HTML — с M1 | Не делались. Блокировка писателя уже есть, и параллельные записи в разные темы не теряются (проверено восемью процессами), но конфликты двух сессий владельцу пока не показываются |

## 2. Открытые решения §8.6 — что выбрано на M0

| Решение | Выбор M0 | Почему и что остаётся открытым |
| --- | --- | --- |
| Язык ядра и доставка | Python 3.8+ только со стандартной библиотекой; поставка как плагин Claude Code (репозиторий одновременно маркетплейс) или как папка скилла | На macOS python3 приходит вместе с инструментами командной строки, которые нужны и для git; в Linux он есть почти всегда. Windows не проверялся: в хуках плагина стоит `python3` |
| Схемы записей | Внутренняя схема `atlas.m0.1`: транзакция = `{tx, id, at, origin, records[], hash}`, запись = `{id, kind, data, source, at}`. Проверки — в коде (`ops.py`), операции описаны в `references/receipts.md` | Исполнимая JSON Schema, коды ошибок и миграции открыты. При другой версии схемы ядро останавливается и просит миграцию, но ничего не переписывает молча |
| Граница наблюдаемого свидетельства | Первый адаптер запуска, которому доверяет протокол, — само ядро: `atlas.py check -- <команда>`. Ядро запускает команду без shell, записывает код завершения, хвост вывода и отпечаток состояния до запуска | Модель угроз: агент может запустить бессмысленную команду и приписать её условию. Защита только частичная: команда и условия сохраняются в записи (`atlas.py show`), а условия нужно назвать явно. Качество теста протокол не оценивает (B.2) |
| Идентификация версии результата | Отпечаток по **содержимому**: идентификаторы blob всех отслеживаемых и неигнорируемых неотслеживаемых файлов, без `.atlas/`. Коммит и `git add` того же содержимого отпечаток не меняют, любая правка меняет. Неотслеживаемые артефакты сборки и кэшей (`__pycache__`, `.pytest_cache`, `node_modules`, `dist`, `build`, `*.pyc` и т. п.) в отпечаток не входят: иначе каждый запуск теста «менял бы версию» | Внешняя конфигурация, базы данных и переменные окружения в отпечаток не входят. Исходники в неотслеживаемой папке `build/` или `dist/` тоже не учитываются. Без git версия не привязана к коду, и карточка результата говорит об этом прямо |
| События агентов | SessionStart: `startup`/`clear`/`resume` дают доклад владельцу (`systemMessage`) и сводку агенту (`additionalContext`); `compact`/`fork` — только сводку. Stop: отметка конца ответа; после трёх ответов подряд, в которых файлы менялись, а записей не было, агенту приходит одно напоминание (`additionalContext`). `stop_hook_active` соблюдается, счётчик после напоминания сбрасывается | Формат сверен с документацией Claude Code (hooks reference, 26.09.2026). Живой прогон на Claude Code 2.1.283 (см. раздел 5) подтвердил сводку при старте и отметку конца ответа. Матрица адаптера E.4 заполнена только частично: `resume`, `compact` и напоминание Stop в живой сессии не наблюдались |
| Политика автономности | Рекомендательный режим: договорённость хранится и целиком входит в сводку; для операций самого Атласа ядро требует слова владельца | Техническая остановка команд агента вне Атласа не обещается (C.4, A51, A54). Владельцу это сказано при подключении |
| Приватность и удаление | `.atlas/.local/` не уходит в git (`.atlas/.gitignore`); «как прошло» — в `.local/private/`; тексты, похожие на секреты, писатель отклоняет; `atlas.py redact` чистит записи и оставляет маркер | Срок хранения и резервные копии открыты. Ограничения удаления перечисляются владельцу: git-история и уже отправленное модели |
| Порог «буксуем» | Не реализован (M2). Попытки уже записываются с признаком «новый подход» | Пороги открыты |
| Слово для «решили не делать» | «отпущено», как в ТЗ | Проверяется в интервью |

## 3. Другие решения реализации

- **Одна квитанция — одна транзакция — один файл** `NNNNNN.json`. Номер растёт на единицу. Если номер пропущен, повторён (например, после слияния веток git) или не сходится контрольная сумма, загрузка останавливается на последнем целом файле, и новые записи не делаются (E.3).
- **Наблюдение и команда (E.1).** Наблюдения (`note.*`, `attempt`, `park.add`, `verify` и др.) сохраняются, даже если команда из их группы получила конфликт. Группа (`group`) применяется по принципу «всё или ничего»; режим владельца «только целиком» — `all_or_nothing`.
- **Предусловия (E.2):** `expect` (ревизии) и `base_snapshot` (снимок из сводки). Изменение темы, решения по теме или договорённости по теме в **другой** сессии после снимка даёт конфликт.
- **Доставка решений (C.2):** «записано» → «получил» (решение было в сводке сессии или его записала сама сессия; `decision.ack`) → «учтено» (`decision.applied`, со слов агента). Механизм передачи сообщений между сессиями, который есть в платформе, пока не используется.
- **Неполная запись (§6.1).** Ядро видит три случая и не догадывается сверх них: сессия меняла файлы, но конец ответов не отмечен; сессия меняла файлы и не оставила записей; файлы менялись после последней записанной сессии. В ручном режиме полнота записи не известна по определению, и это показано как режим, а не как сбой.
- **Технический старт — не визит владельца** (F15, A76). Записи ядра («старт сессии», «пробел записи») не считаются работой другой сессии.
- **Слова словаря (§4.2)** поясняются при первом появлении в сессии. Какие слова уже пояснены, хранится в локальном манифесте сессии.

## 5. Живые прогоны (26.09.2026, Claude Code 2.1.283, `claude --plugin-dir`)

Три коротких прогона на учебном проекте. Это проверка связки, а не пилот.

1. **Старт сессии.** Хук плагина сработал, сводка «[Атлас] …» оказалась в контексте агента, конец ответа отметился в манифесте сессии.
2. **Надиктовка из ТЗ (Э5).** «Давай доделаем вход… потом нужна тёмная тема… не уверен, что цена 9 $ правильная… мы же решили не делать регистрацию по телефону… может, стоит онбординг». Агент загрузил скилл, нашёл прошлое решение через `find` и не создал нового; тёмную тему и онбординг записал в парковку как идеи, цену — как вопрос. Ответ показал по форме Э5. Что пришлось исправить по итогам первых попыток:
   - пока шаблоны экранов лежали только в справочнике, агент их не открывал и отвечал списком — теперь шаблоны Э5, Э6 и Э11 стоят прямо в SKILL.md;
   - агент не загружал скилл, пока сводка и блок в CLAUDE.md прямо этого не требовали — теперь требуют;
   - Claude Code блокирует heredoc с JSON («expansion obfuscation»), поэтому основной путь записи теперь файл `.atlas/.local/inbox/*.json` и `write --file`.
3. **Полный цикл.** Агент написал код и тест, предъявил результат, запустил `atlas check` («проверено 1 из 1, тестом на компьютере») и показал карточку Э4. Найдено и исправлено: `__pycache__`, оставшийся после теста, менял отпечаток версии и вызывал ложное «код менялся после предъявления».

## 6. Известные ограничения прототипа

- Живые прогоны были короткими и проходили на одном учебном проекте (раздел 5). Первый шаг пилота — подключить Атлас к реальному проекту автора.
- `systemMessage` при старте показывается в терминальном клиенте. Если в каком-то клиенте его не видно, есть настройка `atlas.py prefs report_at_start agent`: тогда доклад покажет агент первым ответом.
- Отпечаток версии пересчитывается на каждом конце ответа. В очень больших репозиториях это может заметно замедлить хук; таймаут хука — 30 секунд.
- Номера вопросов и решений общие («вопрос 2», «решение 3» идут одним счётчиком). Номера не переиспользуются.
